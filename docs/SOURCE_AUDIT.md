# 发布源码整理与检查

## 检查范围

检查了准备提交的主工程、五个仓库内模块、构建与图标脚本、应用元数据、资源和文档，其中包括 158 个 Swift、C 与头文件。

`.build/` 与 `dist/` 属于本地构建和历史备份，不属于准备提交的源码。原先同级的其他开发项目未修改，也没有把它们的研究资料或构建缓存复制进仓库。

## 名称与文案

- 扫描并人工查看了已知参考产品的名称、大小写变体、包路径和应用标识出现的位置。
- 清理比较式注释、显示提示、界面说明和相关的硬编码应用检测条目；不是通过编码或运行时拼接隐藏名称。
- 监控库的内部项目名统一为 `MonitoringLab`。原宿主已经保存的设置继续保留；不再迁移未公开旧监控项目的偏好。
- 对整理后的源码、脚本、文档和资源重新扫描，已知参考产品名称未命中。
- 对最终主程序和两个助手的二进制字符串复查，上述名称也没有命中。
- 系统 API、通用技术名词和项目自己的模块标识保持正常命名。

Meridian 不硬编码第三方应用的 Bundle ID，也不提供按名称退出其他应用的操作；遇到输入或硬件冲突时按手册逐项暂停相关功能排查。

## 授权与资源

- 添加 0BSD LICENSE 与 NOTICES、贡献说明。许可覆盖贡献者有权授权的内容。
- 检查了纳入源码中的版权、许可证与复制来源注释，没有删除要求保留的版权或授权声明。
- 未纳入外部传感器 XML；新构建包只保留标准图标与两个启动配置，不再包含传感器表。
- 传感器目录使用代码中已有的内置候选集；保留温度曲线所用的稳定 CPU 分组标识。该目录不具备完整机型语义保证，尚未重新做硬件控制实测。
- 检查了常见私钥、GitHub token、云访问密钥及 API token 格式，并检查准备提交的文件清单，没有命中上述格式或证书私钥文件。

文本和格式扫描不能排除所有秘密信息，也不能证明代码完全独立或没有权利争议。未来引入外部内容仍须检查真实来源和条款；本次没有做法律鉴定。

| 本地 Markdown 文件链接 | 通过 |

构建有现有的并发注解、私有 API 头文件 nullability 以及 Command Line Tools 搜索路径等警告，没有把这些警告当作跨版本兼容已经解决。

独立副本验证的是仓库内依赖是否完整；它仍使用同一台开发机的工具链，不能替代另一台 Mac 的首次安装测试。模块检查在隔离偏好域运行，不安装 root 服务、不切换真实显示模式，也不验证手动风扇控制。

本次没有执行完整的安全审计、逐段来源鉴定、跨机型测试、公证、远程推送或 GitHub Release 发布。管理员助手和硬件控制的剩余事项见 [RELEASING.md](RELEASING.md)。

本机详细构建与检查日志保存在忽略目录 `.build/release-preparation/`。
