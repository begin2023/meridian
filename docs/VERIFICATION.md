## 本轮修复（用户反馈后）

- **5K HiDPI 实际不可用**：显示模块 创建的 5K 虚拟屏没有“看起来 2560×1440”的 Retina 模式，系统默认落到 1920×1080。
  用新增的 `ddcprobe virtual-modes` 探测确认后，改为显式声明半尺寸模式，并在镜像前后选中、核验目标模式，不符即自动还原。
- **5K 开启后无法关闭**：镜像中的物理屏不在活动显示器列表里，界面会丢失该屏；枚举改为同时包含硬件镜像中的在线屏。
- **“恢复原生”选错模式**：同像素的 HiDPI 模式（看起来 1280×720）被当成原生；改为优先 1× 模式。
- 分辨率列表里 HiDPI 项改为显示“看起来像”的尺寸；5K HiDPI / 5K 更多空间直接列在分辨率选项里，并在下次启动时恢复。
- 风扇：去掉与顶部重复的“自动/固定/按温度”；温控曲线与固定转速改为拖动只改草稿，点“应用”才生效。
- 菜单栏面板详情页去掉“返回”，顶栏统一为“⊞ Meridian › 页面名”，点 ⊞ Meridian 或菜单栏图标回到首页。

## 第二轮反馈修复（2026-10-31 晚）

- **5K 渲染闪屏**：5K 上采样改为默认固定 60Hz（可在“显示器”页打开“跟随显示器刷新率”恢复 144Hz），
  并对虚拟屏显式选择“点数 = 像素/2”的 Retina 模式、在镜像前后用点数/像素双重核验。
  实测 60Hz 与 144Hz 两种模式均能输出 5120×2880、看起来 2560×1440，系统报告 144Hz；
  5K 镜像下连续 20 秒无显示器重配置事件、无模式翻转。系统自行拆掉镜像时会丢弃幽灵会话，
  界面不会再出现“显示 5K 已开启但实际是原生”的状态。
- **风扇与转速不显示**：面板里的风扇卡片正常（实测 1,188 RPM）；原因是偏好重置后菜单栏默认小组件
  只有 CPU/内存/网速，风扇小组件被关掉了。默认小组件现加入“风扇”，升级后重启即出现在菜单栏。
- **屏幕录制授权要手动添加**：原来的“去授权”在调用系统请求后立刻打开“系统设置”，会把系统授权提示挤掉，
  macOS 因此不会把 Meridian 登记进权限列表。现改为：先激活 Meridian → 只发起系统请求，
  “系统设置 / 在访达中显示 Meridian”作为单独的按钮；授权横幅里直接提示“列表里没有就拖进去”。
- 5K 选择写入后立即 synchronize，避免应用被强杀时丢失“下次启动恢复 5K”的偏好。

## 第三轮：HDR、HiDPI 档位与刷新率（2026-11-01，对照 BetterDisplay 5.2.1）

测试前退出 BetterDisplay。对照它的二进制（导入符号与文案）确认它切 HDR 用的是同一组
`SLSDisplay*HDRMode*`，差距在周边处理，按下面几点改：

- **不再用虚拟屏做“5K 渲染”**：旧版启动时按 `meridianUpsample.*` 偏好自动建 5K 虚拟屏并镜像，桌面渲染在
  8-bit SDR 虚拟帧缓冲上，HDR 被截断，默认还锁 60Hz。面板本身就有 2560×1440 HiDPI（5120×2880）@144Hz，
  现在分辨率只列同比例 HiDPI 档、直接切物理屏模式，刷新率单独选；遗留偏好在启动时清掉。
  实测 HDR 下 144Hz 连续 20 秒 0 次重配置、0 次模式翻转。
- **模式表单位统一**：CGS 表宽高是点数、公开表是像素，同一模式会出现两次；`DisplayModeInfo` 增加点数字段，CGS 项按 density 换算像素。
- **HDR 切换**：外接屏开 HDR 约 1–2 秒，旧版只等 0.5 秒就报“未能切换”。另外用 CGS 私有接口在 HDR 下切过刷新率/分辨率后，
  再开 HDR 时 WindowServer 只记下请求不执行（日志链路停在 `YCbCr444_8bit`），直到下一次 modeset。
  现在等 2.5 秒未生效就原样重设当前模式把请求冲下去；复现序列（120Hz→1920×1080→原生→144Hz→关 HDR→开 HDR）两轮均在 4–5 秒内开启。
- **HDR 保持**：切分辨率/刷新率前处于 HDR 的，切完若掉出 HDR 自动重开。实测 4 次切换 HDR 均保持。
- **HDR 下的亮度**：改用 DisplayServices 调 macOS 的 SDR 亮度（HDR 下 `DisplayServicesCanChangeBrightness` 为真），
  不再走 DDC 和 gamma 调暗。`meridian://brightness/60` 读回 SDR 亮度 0.6、色表不变；关 HDR 后回到 DDC（读回 63%）。
- **亮度提升**：HDR 下用 4×4 像素 EDR Metal 层保持 EDR 合成（当前余量 1.0→2.1），再写高于 1.0 的色表。
  实测 1024 项色表里高于 1.0 的值会被截到 1.0，256/512 项保留，所以提升时写 256 项。`boost/150` 读回最大 1.5，
  `boost/100` 与关 HDR 都还原到 1.0、EDR 回到 1.0。实际观感需要人眼确认。
- **HDR 时关闭夜览/原彩**（可选，默认关）：夜览状态以第 2 字节 `enabled` 为准（第 1 字节关闭时也为 1）。
  夜览开 → 开 HDR 后关闭 → 关 HDR 后恢复；夜览关 → 全程保持关闭。
- **HDR 虚拟屏**：`CGVirtualDisplayMode` 的 `transferFunction` 为 1 时虚拟屏支持并处于 HDR（0/2/3 不是）；
  界面创建的 1080p HDR 虚拟屏 `SLSDisplayIsHDRModeEnabled` 为真。macOS 27 新建虚拟屏会弹系统的“镜像/窗口/扩展”选择框。
- **HiDPI 档位**：覆盖文件改写为同比例 7 档（1280×720 … 2880×1620，帧缓冲宽不超过 6144）；
  界面直接读覆盖文件判断“未写入/需更新/已是最新”，不再依赖助手的 list。旧版写入的 2 档文件会显示“更新…”。
- `swift run --package-path Modules/Display DisplayLabKitSmoke`：PASS。

## 第四轮：HiDPI 开关、面板分辨率列表与截图历史（2026-11-01）

- **展开分辨率后截图快捷键失效**：面板里的“分辨率”原来是系统菜单，菜单打开时独占键盘，Carbon 全局快捷键
  （⇧⌘A）既不触发也不排队，关掉菜单后也不会补发。实测：菜单窗口（层级 101）在屏时发送快捷键，日志无任何截图记录。
  改为在面板内展开的列表，不再弹系统菜单；展开后屏幕上没有菜单窗口。
- **HiDPI 开关**：面板与显示器页各加一个 HiDPI 开关，在当前尺寸的 HiDPI 与普通模式之间切换，保持刷新率；
  该尺寸没有另一种模式时开关置灰并说明原因。
- **分辨率列表**：每个同比例尺寸一行，行尾标签显示这一档是 HiDPI 还是普通；有两种模式的尺寸按当前 HiDPI 开关选。
  面板实测列出 2560×1440（原生）、2048×1152、1920×1080、1600×900、1344×756、1280×720，均为 HiDPI；
  刷新率改成一排按钮（144/120/75/72/70/60/56/50），不再被截断。
- **截图历史布局**：预览区原来按图片自身尺寸撑开，长图把面板撑高、切换图片时整体跳动。改为固定骨架：
  列表占满左侧高度，预览占满右侧，大图按比例缩小、小图保持原大。实测 3618×2790、740×1398、320×186 三张来回切换，布局不变。
- 未实测：实际点 HiDPI 开关切换模式（会让屏幕黑一下，留给用户确认）。

## F1 / F2 调节外接屏亮度

- 旧实现把亮度键码写成了 `NX_KEYTYPE_ILLUMINATION_UP/DOWN`（21/22，键盘背光），
  真正的亮度键是 `NX_KEYTYPE_BRIGHTNESS_UP/DOWN`（2/3），所以事件监听虽然建立成功，
  按 F1/F2 却毫无反应——不是权限问题。
- 修正后实测：合成系统亮度键（NSEvent.systemDefined subtype 8），连按 3 次亮度+：
  DDC 亮度 36 → 56；连按 3 次亮度−：回到 36。
- 权限兜底：事件监听创建失败时会自动请求“输入监控”，并在显示器页显示
  “F1/F2 还没有生效”提示（输入监控/辅助功能设置入口 + “重新打开 Meridian”），
  不再静默失败。

## 2026-11-01 风扇温控在重启后看似“已勾选但不生效”

- 现象：退出 Meridian 再打开后，风扇模式仍显示“温控”，但实际由系统固件控制；
  切到“自动”再切回“温控”才恢复。本地干净退出→重开时未复现，两个已安装守护进程都在
  1 秒内重写了 `F0Md=1`，风扇按 60–90°C 曲线运行（CPU 平均约 71.7°C，目标约 2300–2600 RPM）。
- 根因（代码审查）：守护进程只凭进程内的 `appliedModes` 缓存决定是否写 `F{n}Md`。
  睡眠唤醒、固件看门狗或另一份仍在运行的旧守护进程都可能把模式寄存器归零，而缓存仍为 1，
  之后只写 `F{n}Tg` 会被固件忽略；只有模式值变化（自动 → 温控）才会重写，正好对应上述绕过方式。
- 修复：守护进程每拍读回 `F{n}Md`，与期望值不一致就重写，不再只信缓存；删掉无用的 `appliedModes`。
  应用侧比较包内与已安装的守护进程，不一致时在散热页显示“更新…”并在切换非自动模式时引导更新。
- 需重新安装守护进程后修复才生效。睡眠唤醒后寄存器归零的场景尚未实测；可用
  `F0Md` 读回后手动验证。
